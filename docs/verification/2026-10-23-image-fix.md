# Card image production fix

The production browser reproduced six failed images: the hero and five subject cards referenced `/src/assets/images/...` as literal strings. Vite does not emit those source paths in its production bundle. Two other category variants used the development-only `/public/assets/...` prefix.

The six source images now use explicit Vite imports and are emitted as hashed files under `/assets/`. The English and teacher variants use the correct public paths `/assets/preschool/...`. The original artwork is retained.

TypeScript and the production build pass. The staged deployment returned all eight repaired images with image content types and bytes matching the original files. Released deployment: `dpl_m55QK7pavx8Mn8VWmGAcbgExW5U7`.

Production browser verification on `https://khuvuontrithuc.vercel.app/` passed: all seven rendered homepage images decode, no broken images, and both additional category artworks decode. Desktop and 390px mobile checks pass. `scripts/verify-card-images.mjs` is now included in the browser suite to catch this regression.

See `card-images.json`, `card-thumbnails-desktop.png`, `card-images-desktop.png`, and `card-images-mobile.png` for evidence. Browser cache is disabled during the check so it verifies the released bundle.
